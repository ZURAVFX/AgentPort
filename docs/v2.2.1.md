# AgentPort 2.2.1

Fixes Harness startup failing with `settings-file: DUPLICATE_KEY` after selecting a model.

The old settings writer could add a second `llm-pi-ai` section when Harness had saved `providers: {}`. Model and preset changes now use a shared YAML-aware writer instead of text insertion. Compatible duplicate maps are merged; conflicting values stop the update without guessing. Settings are backed up before changes and the generated document is validated before replacement.

The YAML parser and its licence are bundled with AgentPort. No extra parser installation is required.

Existing AgentPort-created fast presets are also migrated from the old persona `text` setting to Harness's required `prefix` setting, preserving the instruction text and a backup. Newly installed presets use the current format.

This is a startup/configuration fix, not a change of inference backend or a new speed benchmark. Regular GGUF files continue to use the managed GPU backend. NInfer remains an optional specialist backend.

## Verification

The `--integration-current-model` diagnostic starts the model selected in AgentPort, checks Harness's authenticated page and the backend completion endpoint, then sends a short prompt through Harness using its default model. It creates a conversation named **AgentPort startup verification**. Closing the diagnostic stops its runtime stack.

Verified on Windows / RTX 4080 16 GB with the user's Qwen3.8-27B-Uncensored-Q3_K_S GGUF at 65,536 context: Harness started, and the selected model answered the test prompt. The cold Harness prompt included approximately 42k input tokens and took about 33 seconds; this test does not establish interactive latency for every preset or task. Isolated settings regression tests pass under Windows PowerShell 5.1 and PowerShell 7.
