# AgentPort v1.6 setup and discovery plan

This build should make AgentPort feel obvious for a first-time user.

The main product promise is:

> Connect local GGUF AI models to DeepSeek Harness on Windows.

## Problems to fix

- DeepSeek Harness setup can fail silently or feel broken.
- TextGen and DeepSeek Harness do not have obvious install buttons.
- Users cannot immediately see whether required components are installed.
- GGUF plus helper-file workflows, such as `mmproj`, are not explained clearly.
- Local models from tools like Ollama, LM Studio and Unsloth Studio are not discovered automatically.
- The Skills page lists skills but does not make adding a skill easy.
- Startup phase text contains broken characters, for example `Â·`.

## New setup status panel

Add a setup panel on the Home page and Settings page.

Each dependency gets a clear status:

| Component | Status examples | Action |
|---|---|---|
| TextGen | Installed / Missing / Needs repair | Install, Repair, Open folder |
| DeepSeek Harness | Installed / Missing / Needs repair | Install, Repair, Open folder |
| Models folder | Ready / Empty / Missing | Open, Change, Scan |
| Harness skills | Ready / Empty / Missing | Add skill, Open folder |

Status should be based on real checks, not just saved paths.

## TextGen detection

TextGen is installed when the configured folder contains either:

- `start_windows.bat`
- `server.py`
- `installer_files/env/python.exe`

If some but not all files exist, mark as **Needs repair**.

## DeepSeek Harness detection

DeepSeek Harness is installed when the configured folder contains:

- `package.json`
- and either `node_modules`, `pnpm-lock.yaml`, or a valid package manager setup

If `package.json` exists but dependencies are missing, mark as **Needs repair**.

## Installer buttons

Add simple buttons:

- **Install TextGen**
- **Repair TextGen**
- **Install DeepSeek Harness**
- **Repair DeepSeek Harness**
- **Open install folder**

The install flow should show clear phases:

1. Choose install location
2. Download or clone
3. Install dependencies
4. Verify files
5. Mark ready

Do not hide failures. Show the latest command output in the log panel.

## Model discovery

Add a **Scan for existing models** button.

Scan these sources:

| Source | Detection strategy |
|---|---|
| AgentPort/TextGen | Configured `models_root` |
| LM Studio | `%USERPROFILE%\.lmstudio\models`, `%APPDATA%\LM Studio\models` |
| Ollama | `OLLAMA_MODELS`, `%USERPROFILE%\.ollama\models` |
| Unsloth Studio | `UNSLOTH_STUDIO_HOME`, `%USERPROFILE%\.unsloth\studio`, `%USERPROFILE%\.cache\huggingface\hub` |
| Hugging Face | `HF_HOME`, `HUGGINGFACE_HUB_CACHE`, `%USERPROFILE%\.cache\huggingface\hub` |
| Jan | `%USERPROFILE%\jan\models`, `%APPDATA%\Jan\models` |
| GPT4All | `%LOCALAPPDATA%\nomic.ai\GPT4All`, `%APPDATA%\nomic.ai\GPT4All` |

For every `.gguf` file found, show:

- model file name
- source app
- full path
- file size
- probable quant type, for example `Q5_K_M`
- helper file status

## GGUF helper files

Some models need related helper files, especially vision/multimodal models using `mmproj`.

AgentPort should detect helper files in the same folder, including:

- `mmproj*.gguf`
- `*mmproj*.gguf`
- files sharing the same model family name

The UI should show:

- **Text-only GGUF** — no helper needed
- **Multimodal GGUF** — helper detected
- **Multimodal GGUF** — helper missing or unknown

The user should not need to understand this first. The app should explain it simply:

> This model may need a helper file for image/vision features. Text chat can still work without it.

## Skills page

The Skills page should become action-led.

Add buttons:

- **Add skill folder**
- **Import skill ZIP**
- **Create blank skill**
- **Open skills folder**
- **Refresh**

Each listed skill should show:

- skill name
- folder path
- detected files
- compatibility status
- remove button

Basic compatibility check:

- contains `skill.md`, `README.md`, `.md`, `.py`, `.js`, or `package.json`
- otherwise mark as `Needs review`

Copy imported skills into:

```text
%USERPROFILE%\.dsh\harness_skills
```
