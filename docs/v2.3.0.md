# AgentPort 2.3.0

Windows can reserve port ranges for WSL and virtual networking. AgentPort now checks whether its preferred backend port can be bound and selects an available alternative when Windows denies it. The selected port is saved and shared by the backend, Harness, background status checks, and stop controls.

Startup failures now display the current managed backend log instead of an old TextGen log. Fixed the model scanner showing only `C` for a single helper file. Model input declarations use Harness's `input` field and preserve arrays for text-only models.

Verified locally on an RTX 4080: Windows reserved port 5100; Ridge with its BF16 vision projector loaded on selected port 15100 at 131,072 context and returned a completion. The packaged EXE also passed a real request through DeepSeek Harness, returning READY. This confirms startup and text inference, not image-understanding quality. Settings and port-selection regression tests passed.

Harness shutdown now recognises the Windows `node_modules\\.bin\\..\\` path form used by npx and preserves ownership of the intermediate AgentPort wrappers. Local Harness fallback matching is restricted to a path boundary and a recognised dsh entrypoint. The packaged stop core was exercised against a live owned Harness chain and closed port 3080 without targeting unrelated processes.

The shipped launcher no longer uses PowerShell `ExecutionPolicy Bypass`. Releases can be signed through Microsoft Artifact Signing when the repository's signing variables and secrets are configured.
