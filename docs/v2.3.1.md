# AgentPort 2.3.1

Home now separates the local model from DeepSeek Harness, with a status line and clear actions for each:

- **Unload model** releases the model runtime without closing Harness or deleting model files.
- **Close Harness** stops the agent service without unloading the model. Saved chats remain; an existing browser tab may remain visible.
- **Open Harness / Show Harness** opens the interface without reloading a running model.
- **Stop both & free memory** stops both AgentPort runtimes, leaving other apps alone.

Actions show immediate loading feedback. Failed stops retain ownership information for a retry and report the affected processes instead of displaying a false success. Startup cannot respawn a model after an Unload or Stop both request. Old runtime snapshots cannot mark a newly loading model Ready.

The ownership checks now support the repeated backslashes emitted by npm's Windows launch shim. Exact creation timestamps survive PowerShell 5.1 background-worker serialisation, and shutdown verifies process exit rather than relying only on the disappearance of a listening port.

The update pipeline calculates its checksum after optional signing, so the checksum always describes the distributed bytes. Signing is not yet configured; these changes do not guarantee that Windows Defender will accept an unsigned release.

## Validation

- Windows PowerShell 5.1: real independent-process fixtures, unrelated-listener preservation, failed-stop reporting and non-listening survivors.
- Production Home XAML and button handlers: all four model/Harness states, busy feedback, reopen, timeout and failure recovery. Minimum-width control layout rendered and inspected.
- 19 startup regression cases, including reentrant stop clicks and stale Ready snapshots.
- Existing robustness, settings and backend port-selection tests passed.
- Packaged EXE, Windows / RTX 4080 16 GB: Ridge GGUF with its BF16 projector at 131,072 context completed real Harness replies before stopping, after reopening Harness, and after reloading the model. Process identity checks proved that Close Harness kept the model unchanged, and Unload/reload kept Harness unchanged. Both endpoints closed after Stop both. This verifies text inference and lifecycle behaviour, not vision quality or a new performance benchmark.
